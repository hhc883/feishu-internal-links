# 飞书内链助手（多维表格测试版）

## 安装与连接

1. WordPress「插件 → 安装插件 → 上传插件」，上传 ZIP 并启用。建议先在测试站点使用。
2. 在飞书开放平台创建企业自建应用，开通多维表格查看、评论和导出等足以读取字段和记录的应用身份权限。创建版本并发布，企业管理员按实际流程审批并启用。
3. 打开多维表格，在「…」→「更多」→「添加文档应用」中添加该应用并授予读取权限；如开启高级权限，还需设置对应的数据表访问权限。仅将文档分享给个人账号不等于给应用授权。
4. WordPress「设置 → 飞书内链」中填写应用的 App ID、App Secret 和多维表格 /base/ 链接，保存后点击「同步飞书关键词库」。不要将 App Secret 发到聊天中。
5. 插件使用多维表格自己的 /base/ 链接，不使用嵌入它的外层 /docx/ 文档链接。如果链接不含 table 参数且应用可以访问多张数据表，需要在设置页额外填写目标数据表的 ID（tbl 开头）；只有一张可访问数据表时可留空。
6. 在区块编辑器右上角的更多选项（⋮）打开「飞书内链」，点击「识别内链」，检查匹配列表后点击「确认添加」，最后检查正文并保存。

## 表格字段

字段名称须完全一致：

| 字段 | 类型 | 内容 |
| --- | --- | --- |
| 关键词 | 文本 | 每条记录一个关键词 |
| 内链地址 | 超链接或文本 | 完整的 HTTP 或 HTTPS URL |
| 状态 | 单选 | 启用 或 停用 |

目标链接可以指向任意域名，包括本站页面和外部网站。同一关键词不可对应不同 URL；停用记录被忽略。同步任一有效记录有格式错误时，插件提示记录 ID，保留上次成功的规则。空表或没有启用规则会清空已同步规则。同步完成后重新打开编辑器以读取最新规则。

## 匹配范围

在「设置 → 飞书内链」勾选「仅匹配当前站点链接」，编辑器就只使用与 WordPress 首页域名相同的目标地址。例如 `www.example.com` 和 `example.com` 视为同站，`blog.example.com` 单独判断。开关默认关闭，允许使用全部已同步的规则。切换后保存设置并重新打开文章编辑器即可生效，飞书关键词库无需重新同步。

仅处理段落和列表项文本，跳过标题、已有链接、代码及其他区块。设置页可调整每次识别最多添加数量（默认 10）和每个目标 URL 每篇最多出现次数（默认 1），范围为 0–1000，0 表示不限制。每篇限额计入正文已有链接及本次添加的链接；不同关键词指向同一 URL 时共享该限额。每次识别数量不包含已有链接，多次识别可让文章累计添加超过该值。指向当前文章的链接依赖编辑器提供固定链接。匹配不区分英文大小写，英文词首尾按字母、数字和下划线判断边界；不匹配跨多个文本节点的关键词。同一位置优先较长关键词。预览后文章变化时须重新识别。确认后可使用编辑器撤销，并请在发布前检查。

## 文章链接检查

在各自的 WordPress 后台打开「设置 → 文章链接检查」，填写以下三项。

- **对外访问地址**是读者访问当前站点时用的地址，也是插件生成新链接时采用的地址。填写协议和域名，例如 `https://ipfly.io`。这一栏填到域名为止。
- **对应站点域名**是另一套后台对应的域名。插件用它识别草稿中从另一站带过来的链接。这里只填域名，例如 `ipfly.net`，省略协议和路径。
- **本站 sitemap 地址**每行填一个完整的 XML sitemap 或索引网址。主站和博客各语言有独立的 sitemap 时，可同时填写，例如 `https://www.ipfly.net/sitemap.xml`、`https://www.ipfly.net/blog/sitemap.xml` 和 `https://www.ipfly.net/blog/zh-cn/sitemap.xml`。候选路径收录在任意一个已填写的 sitemap 中即可参与访问校验。

| 你在哪个后台配置 | 对外访问地址 | 对应站点域名 |
| --- | --- | --- |
| `.io` 后台 | `https://ipfly.io` | `ipfly.net` |
| `.net` 后台 | `https://www.ipfly.net` | `ipfly.io` |

例如在 `.io` 后台，插件会把草稿中的 `https://www.ipfly.net/blog/example/` 识别为来自对应站点的链接，并检查 `https://ipfly.io/blog/example/`。带 `www` 和不带 `www` 都可用于识别。插件生成候选地址时使用「对外访问地址」里配置的写法，因此 `.io` 后台填写 `https://ipfly.io` 也能纠正误带 `www` 的本站链接。

清空「对应站点域名」和「本站 sitemap 地址」即可在编辑器里隐藏文章链接检查。

在 WordPress 区块编辑器中打开侧边栏「文章链接检查」。所有你有权编辑的文章都可以检查，包括已发布的文章。点击检查后，可预览段落、标题、列表、表格、图注等正文中的超链接。插件在 sitemap 中匹配候选路径，并检查候选地址能否从服务器访问。结果用绿色显示匹配成功，用红色显示匹配失败及原因。查找路径时忽略查询参数和锚点，替换时保留它们。点击「确认处理」后，检查编辑器中的修改，再使用 WordPress 的保存或更新按钮。

使用 Polylang 的同域名语言目录时，先为文章选择语言并保存。如果刚切换语言，保存后刷新编辑器。对于来自对应站点的链接，插件先识别来源的 `zh-cn`、`zh-tw` 及本站 Polylang 已配置的语言目录，再按照当前文章语言生成目标地址；英文是默认语言且没有独立目录时会去掉来源语言目录。主站和博客均适用。例如 `.net` 的 `/blog/zh-cn/example/` 在 `.io` 繁体文章中会匹配 `/blog/zh-tw/example/`，在英文文章中匹配 `/blog/example/`。手动映射的目标也按当前文章语言调整。目标语言页面必须在 sitemap 中且可访问；不会在目标语言缺失时静默替换为其他语言。无法识别文章语言时保留来源路径，不能保证语言转换。本站已有链接仍按原有检查范围处理。

每条匹配失败的链接都可以单独选择「保留原链接」或「移除链接（保留文字和格式）」。后台设置决定已确认未收录的链接预选哪一项。sitemap 读取不完整或候选地址无法确认可访问时，预选保留原链接。PHP 需要启用 DOM 扩展。sitemap 数据会缓存 5 分钟。文章链接检查可以独立使用，无需配置飞书。

路径发生变化时，可在「设置 → 文章链接检查 → 已知链接对应关系」中每行填写一组完整地址，用 `=>` 分隔，例如 `https://www.ipfly.io/isp-proxies/ => https://www.ipfly.net/zh-cn/isp-proxy-service/`。左侧必须属于对应站点，右侧必须属于本站，且不含查询参数或锚点；原链接的参数和锚点会附加到目标上。映射目标仍需在 sitemap 中且能从服务器访问。

没有精确匹配或映射时，插件会在已读取的 sitemap 中按路径词语寻找同一语言、同属主站或博客的相似页面，并只展示能够确认访问的候选地址。相似候选默认不选中；在结果的「处理方式」中选择候选并点击「确认处理」后才替换。该功能根据 URL 路径匹配，不读取页面标题或理解语义，因此可能找不到候选，也可能提供含义不同的页面，请逐条核对。未出现候选时仍按后台设置的未匹配链接默认处理方式预选；不希望自动预选移除时请将其设置为「保留原链接」。

## 注意

多维表格接入尚未在真实授权环境和 WordPress 环境完成端到端验证。可在设置页选择每小时、每天、每周或关闭自动同步，并设置站点时区下的时间。每小时选项按所选时间的分钟执行；每周选项可选择星期。默认每天 03:00，升级后请核对设置。插件通过 WordPress 定时任务执行，也支持手动同步。低流量网站可能延迟执行；若禁用 WP-Cron，需由服务器定时调用 wp-cron.php。同步不修改已有文章。App Secret 保存在 WordPress 数据库，需保护服务器和数据库备份。高级权限或飞书租户限制可能需要管理员额外配置。
